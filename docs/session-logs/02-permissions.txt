  How the rules work. I checked these against Claude Code's settings reference.
  - Command rules: Bash(...) with a trailing * matches any command that starts
    with that text.
  - File rules: Read(path) and Edit(path) match files, and Edit covers Write
    too. ./ means relative to the project root.
  - Precedence: deny beats ask, and ask beats allow. So git push --force is
    blocked even though git push* is in ask, and git commit --no-verify is
    blocked even though git commit* is allowed.

  The deny rules are narrower than they look:
  - Flag order matters. Matching only looks at the start of the command, so git 
    commit -m "x" --no-verify and rm -fr would slip past the deny rules. git 
    push origin main --force doesn't run either, but it gets a prompt from the
    git push* ask rule rather than being blocked. If you want, I can add the
    common variants (rm -fr*, git push --force-with-lease*).
  - Shell commands can still read .env. Read(./.env) only blocks Claude's
    file-reading tool. A shell command like cat .env isn't allowed, so it would
    still prompt, but it isn't blocked outright.
  - Only .env itself is denied. A pattern like .env.* would also block
    .env.example, and you can't carve out an exception from a deny rule. So
    .env.local and similar files aren't covered; I can add them by name if
    you'll have them.
